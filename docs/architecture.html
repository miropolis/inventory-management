Factory Inventory Management System

Architecture overview: a three-tier demo app with a Vue 3 frontend, a FastAPI backend and in-memory JSON data (no database).

System architecture

All components run locally. The browser talks directly to the API over HTTP; CORS is open for development.

Data flow

How a filter change on a page becomes updated UI.

  1. User changes a filterPeriod, Warehouse, Category or Order Status in FilterBar updates the shared refs in useFilters.
  2. View reactsA watch on the four refs in the view (for example Dashboard) calls getCurrentFilters() and reloads.
  3. API client builds the requestapi.js skips values equal to all and sends the rest as query params.
  4. FastAPI filters in memoryapply_filters and filter_by_month (month or quarter) run over the preloaded lists.
  5. Pydantic validates the responseTyped response_model shapes the JSON returned to the browser.
  6. Vue rendersRaw data is held in refs; charts, totals and tables are computed properties.

Observations

Gaps found while reading the code, relevant before extending the system.

  • client/src/api.js defines task endpoints (/tasks) and purchase-order endpoints (/purchase-orders), but server/main.py does not implement them. Calls to these would return 404. purchase_orders.json is only read to compute has_purchase_order on backlog items.
  • Both the API base URL (http://localhost:8001/api) and the port are hard-coded; there is no environment-based configuration.
  • CORS allows all origins and there is no authentication; this is suitable for local demo use only.
  • Filters are applied by scanning Python lists, which is fine for demo-sized data but would need a database and pagination to scale.
